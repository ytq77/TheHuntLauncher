# 验证范围

客户端、服务端合仓后的状态统一见[当前验收表](../../docs/validation-current.md)。历史阶段的待办不能覆盖后续已完成的实机反馈。

## 无缝专用版本（preview.16）

本版仅精简 Windows 管理、命令行与打包范围，不更改固定的 shadNet 协议实现、BBSC 游戏服务、Relay、两秒召唤间隔或数据库格式。验证聚焦单一无缝入口、完整开服组件、账号维护与备份、旧普通模式请求拒绝、遗留普通文件保持不变、退出回收，以及干净包不含普通模式。实际执行结果随本轮构建记录提供。

本次 `server/recipe` 的 Linux 构建和协议回归由 preview.16 CI 完成；既有私人部署没有自动重建。此前实机结果按相同底层代码复用，不要求为移除模式选择重复战斗、Boss 或客户端存档验收；协议和进程检查不扩大为新增游戏内验收。

## 已有记录

- Windows 原生 test3：本地编译、上游召唤 broker CTest、打包后的运行库隔离、中文空格路径、两模式同时启动、账号注册登录和隔离、重启持久化、两类 STUN、召唤注册/搜索/领取/投递、BBSC ss.info、双向 Relay、停止释放端口通过。
- 本机登录回归：服务只监听另一回环地址时，原始实现返回未监听的 127.0.0.1；补丁版的登录地址可达、LoginResponse 成功，召唤地址仍指向独立 WebAPI。用户在实际 Windows 开服电脑确认能进入在线。
- 既有云端服务：STUN 修复后曾完成两人移动、战斗、死亡保持连接及提灯同行。这是既有环境记录，不代表新 Linux 配方已完成双人实测。
- GitHub Actions 对当前提交的检查结果以仓库工作流为准；容器健康及协议测试不等于游戏内双人验收。

Linux 首次干净构建与协议检查记录：[GitHub Actions Linux 成功任务](https://github.com/ytq77/TheHuntServer/actions/runs/39746020884/job/119714550470)。该任务完成源码构建、上游 CTest、HTTP 登录、四项召唤路由、两种 STUN 封装和 Relay 监听检查。它不接入私人 Tailscale，也不包含双人游戏。

Windows 管理窗口：本地完整构建、实际 WPF 窗口与后台管道、服务启停和账号列表、运行中编辑保护、原生 UTF-8 注册/登录、改名保留 ID、重置密码后的原生登录、删除关联清理、备份完整性、管道关闭及 Windows Job 子进程回收均通过。测试使用独立副本与临时账号，真实账号和现有服务器未参与。

## 尚未覆盖的组合与环境

Windows 实际开服能进入在线、既有双人联机、Boss 后两人不消失、系统菜单退出及指定客机返家保存均已有对应反馈或记录，按版本与未改路径复用。仍缺新公开完整客户端从内置入口开服到双人进游戏的整体观察，以及所有异常退出／身份切换等组合的覆盖；不要求重做已通过项目。客户端模组的问题应同时提供两端日志，不能仅用服务器健康排除。

新 Linux 配方的完整构建和协议回归由 CI 验证；目标云主机的网络、防火墙、Tailscale 权限和两人游戏回归仍需管理员实测。现有生产服务不会由 CI 自动升级。

## 短轮询单变量对照（2026-10-26）

保持原 01 房主及 comp／02 诊断客机，临时将云端游戏服务的搜索／发布间隔从 35／30 秒改为 2 秒。本轮只有一次信令激活，67 毫秒完成客机信令回调，直接调用 JoinRoom，无提前 DEAD、无 claim 超时清理。建房到服务端加入约 3.3 秒，完整双人场景加载约 15 秒，用户确认互见与移动正常。之后已恢复原云端参数。没有证明所有网络、多组玩家及反向房主均已验证；成功轮未记录旧的 174 字节 claim，不能把更早 HTTP 投递写成已证实机制。新启动默认值及请求量边界见 [召唤轮询说明](summon-polling.md)。

## preview.5 发布与私人部署（2026-10-28）

公开包包含提交 `5bedee3` 已有的两秒搜索/发布设置；普通模式不变，本次没有再修改服务逻辑。此前该提交的 Windows 与 Linux CI 均通过；新版本标签构建会完成相同构建与协议检查，并打包新版本。

经用户授权，既有云端部署在确认主服务与 Relay 没有玩家连接后，将持久 Compose 中 gameserver 命令追加 `--summon-interval 2`，只定向重建游戏服务。切换前备份 Compose 及停止后的游戏服务数据；镜像、持久挂载、shadNet 容器和账号数据库均未替换。容器健康和实际 `ss.info` 均确认搜索/发布为两秒；对客户端公开的实际响应已返回两秒设置。这是部署生效核验，沿用此前双人对照结果，不新增实机验收结论。
