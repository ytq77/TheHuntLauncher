# 私服 Relay v2

本候选要求客户端和私服同时升级。`20444/TCP` 由原生 shadNet 提供；Python 游戏服务以 `--relay-port 0` 运行，不再启动旧广播 Relay。原生 `/status` 仅在认证监听成功后返回数值 `relay_auth: 2`。旧服务器会在启动游戏前提示升级；私服认证失败不会退回旧 Relay 或未认证 P2P。显式公共服务器兼容路径单独保留。

## 身份和房间

启动器通过私服原生 Login/GetToken 取得该账号的令牌，Terminate 并等连接结束，再启动游戏。令牌仅传给当前游戏子进程，不进入命令行、配置、日志、GPU 探测或其他辅助进程。

Relay 使用系统随机挑战、HMAC-SHA256 应答、每次连接独立的会话密钥，以及双向严格递增的序号。发送者取自已验证账号，房间与房主从原生 Matching 状态读取；相同地图不构成同一房间。跟随、世界进度、缩放、Boss 等状态仅接受当前房主，客机互伤请求只发给房主。离房、房主迁移、断线、封禁和令牌重置使旧权限失效；客户端同步清除旧缓存，实际游戏内存恢复仍在游戏线程执行。

四类 `/summon_messenger/{create,get,delete,request}` 请求必须携带私服 Bearer。原生 Broker 将招募记录绑定到经过认证的账号和令牌代次，不能凭正文 UserId 或 SessionId 冒领或删除。正文仍保留公共游戏会话所需的原始 ID，兼容公共内容与私服联机分流。

入房前的跨图位置通过签名 `THP2` 单独发给 Broker 实际选中的招募账号，绑定房主原生房间、双方账号、代次与十秒期限；它不授予房间成员权限。删除、替换招募、房主离房、封禁、令牌重置和超时会使待处理位置失效；已经送达的提示通过同代次零期限控制撤销。撤销不能倒退已经完成的合法传送。

## 兼容与边界

Relay 消息具有身份、完整性和重放检查；底层 NP、HTTP、STUN 仍沿用现有传输，没有因此获得加密。部署继续使用受信玩家的 LAN/VPN 和明确的监听地址。STUN 更新要求原生登录与相同来源 IPv4，但同一 NAT 内的 UDP 来源不具备独立密码学证明；未认证的历史公共内容接口也不在本次私服召唤认证范围内。
