# C# WPF 前台与奖杯显示

该前台已纳入 preview.17。下文保留实现及分项验收边界，最新用户反馈见 validation-current.md。

后续的固定字体分区、页面图片、游戏中奖杯浮层与 PC 菜单汉化见 [桌面候选 2](desktop-candidate2.md)。

客户端现在由 `TheHuntLauncher.exe` 直接创建 WPF 窗口并启动 Python 后端，不再通过 PowerShell 加载界面。保留现有 .NET Framework / Windows 环境，不新增 .NET SDK 或单独安装的桌面运行时依赖。PowerShell 仅用于构建、测试及既有更新助手。

启动器与 `server/Server.exe` 共用 `launcher/DesktopTheme.xaml` 和 `HuntTheme.cs` 的字体、侧栏、按钮、表单与颜色。本地开服仍是独立窗口，拥有自己的服务进程；退出游戏或关闭启动器不会停止它。关闭开服窗口会停止它所启动的服务。

原有游戏配置、31 项玩法设置、存档导入、离线转换及旧诊断任务、SSH 管理、本地地址入口和更新继续保留。操作进行中禁止并发修改、更新或直接关闭启动器。密码仍使用当前 Windows 用户 DPAPI 加密，继续兼容旧的 `.private/account.clixml`，不转换真实用户凭据。

## 奖杯

- 只读当前安装的 `data/user/trophies.log`，覆盖此环境全部角色。编号和真实时间是解锁依据；同编号保留最早有效时间。
- 打开启动器、打开奖杯页或手动刷新、启动游戏前、实际运行任务结束后，以及导入／转换成功后刷新。启动前与退出后会等已有读取完成，再取得新快照。
- 游戏异常结束或世界恢复核对失败仍刷新奖杯。奖杯提示与原有错误分开，不掩盖恢复问题。历史解锁在首次打开时不报为“本次新增”。
- 启动前尚无奖杯日志时，只在退出后刷新完整结果，不把首次导入的历史记录称为本次游戏新解锁。未成功建立基线时同样不推算新增数量。
- 读取失败保留并标注上次成功结果；没有成功结果时显示不可用。末行未写完会短暂重试。缓存仅在当前窗口内，不合并其他目录或旧分支。
- 40 项名称、描述、等级与分组由固定 BBport 1.9.5 `ff42e28bbd5ad02939560e039008a7896b26ae41` 的 `bbport_trophies.py` 和 `bbport_lang_trophies.py` 生成。上游将该文本标记为 PSN 官方奖杯文案；未额外调用 Sony 在线服务。
- 图片由固定上游 `bbport_trophy_icons.py` 只读本机游戏 `sce_sys/trophy/trophy00.trp`，在内存显示，不随公开包分发。缺失或不可读时显示占位图，不影响计数。
- 页面不会写入奖杯日志，也不根据 Boss、NPC 或房主进度推断奖杯。0 号白金按实际记录点亮；仅有本体其余 33 项时提示条件满足，不补写白金。DLC 不计入白金条件。

元数据复核：`python -B scripts/generate-trophy-catalog.py --port <固定 BBport 源码目录> --check`。

## 验证与待验收范围

新增自动检查覆盖 C# 原生页面加载、旧凭据双向兼容、功能持久化与范围校验、任务期间关闭／更新／操作保护、本地地址填写、转换备份入口、实际 Python 奖杯读取、失败快照、会话差集和模拟运行任务异常退出。只用临时账号、临时日志与模拟客户端，不启动真实游戏、不修改真实存档。

真实游戏尚未确认的是：新前台从现有安装启动游戏的完整过程，以及该进程正常退出后真实奖杯记录刷新。旧游戏结果验证的是 PowerShell 前台调用链，无法证明新 C# 进程管理和刷新入口；回家后只需针对这两个新增路径验收。奖杯可先核对现有记录，遇到自然新解锁再确认本次新增，不必重复打 Boss。原有商店、徽章、掉落、梦境恢复及退出菜单验收按未改范围复用。

BBport 1.9.5 的新画质设置和实际游戏运行仍沿用原有待验收项；此次前台迁移不改变引擎、BBSC 奖励／进度逻辑或历史灯丢失问题的调查结论。
