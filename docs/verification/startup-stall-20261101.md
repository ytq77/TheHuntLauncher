## 独立诊断构建

scripts/prepare_startup_trace.py 仅接受已核对的候选 1 核心源文件摘要，输出新的观察源码；
不加入默认发行准备链，不覆盖正常核心源文件。观察内容：

- 现有出生点回调开始、结束，以及第一次角色地面设置。
- 额外原生阶段：出生点解析结束（0x01939196）和角色创建入口（0x01939470）。
- 现有加载／游戏 tick 无缝回调自身超过 50 ms 时，记录其耗时。
- 每线程前 120 秒、全进程最多 64 条观察日志；不写游戏内存或寄存器、不另起线程、
  不等待、不访问账号／网络内容。两个新观察点逐字节核对完整非相对指令。
- 日志异常在观察器内捕获，不能越过原生游戏调用边界。

开发侧：诊断单元回归、真实原生跳板执行验证、完整 DLL 编译、依赖名称与签名核对、
ZIP 完整性检查。跳板验证覆盖解析指令的读取结果、创建入口的栈序言、返回值及输入数据；
具体摘要与结果随补丁 verification.json 提供。尚未在真实游戏加载该诊断 DLL，不能
把“增加观察”写成“卡顿已修复”。

下一次正常启动并读档即可获取新的阶段记录。旧日志只有长帧总耗时和两个外围阶段，
不足以区分原生出生点解析、角色创建前等待、无缝回调耗时；因此这次补充观察有明确
新增信息。不需要联机、Boss、商店、奖杯、空枪或退出的重复复测。
