## 原因与改动

原两轮日志中完整准备分别耗时 96.978 / 91.654 秒，其中 Goods 扫描约
54.829 / 51.113 秒，SpEffect 扫描约 37.132 / 35.524 秒。
`TickBbscDuelBellGive` 等待完整就绪；已经拥有猎具的第二轮读档不能说明初始化变快。

改为优先读游戏当前参数仓库，验证 Goods、SpEffect 的类型、索引范围及全部必需行后，
继续原有效果克隆、物品配置和就绪发布。正常加载只轮询小仓库；原生表示已加载而
验证失败时保留经过同样行校验的扫描回退。发放前备份和库存去重逻辑不变。

CUSA03173 1.09 的原生 SpEffect 读取函数 `0x01F28AA0` 从全局 `0x05540340`
检查仓库 `+0x4A8`，再取 `+0x4B0 -> +0x70 -> +0x70`。参数描述表中的
SpEffectParam 类型号 15，与 `0x70 + 15 * 0x48 = 0x4A8` 对应。
候选在此依据之外仍检查运行时完整表头及行范围，不依靠未经验证的裸偏移直接写行。
