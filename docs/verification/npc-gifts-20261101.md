## 原生机制与本次改动

common 的每个赠礼实例使用事件 9040、不同 slot，参数中的个人请求位恰好是 9040+slot。
事件先在请求位已亮时结束，否则检查本地角色为 Human，非 Human 时提前结束，再等待
请求位，最后发放原生 ItemLot。客机提前 End 与整批请求位提前完成的形状高度吻合。

本次在既有 BbscDreamTypeCheckHook 的允许条件中加入 event == 9040；仍受既有
“确实在别人世界、角色为非本地 Human”保护，仍只回答角色 10000 的 Human 检查。
合作及入侵客机都可能触发同一提前 End，因此都应保持这些个人事件等待。
即使关闭梦境互通，也安装这一个类型观察／应答点；其他梦境事件、对话入口和原有
Boss 奖励记录仍受梦境选项保护，不会因赠礼保护而重新启用已关闭的交互。

这不是直接发奖：请求位不被设置／清除，没有补发队列，不更改 NPC、Boss、商店、
装备或存档。只有本人正常对话开启相应请求位后，原生赠礼事件才会继续。
已有受影响存档不会被猜测修复；个人存档定点恢复另有备份与变更清单，不进入发行包。
