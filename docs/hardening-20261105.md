# preview.22 审查后加固候选（未发布）

本候选在 preview.21 `1802e25` 和此前通过定向实测的 preview.22 改动上加固。没有提交、打标签、推送或发布；没有替换实际安装目录、覆盖真实存档或升级正在运行的服务器。历史损坏只提供独立修复副本。

## 改动范围

| 范围 | 当前行为 |
|---|---|
| 当前角色与个人世界 | 通过固定游戏版本的原生完整读档入口、成功返回、当前管理器和槽位确认角色，取消按文件修改时间猜槽位。没有完整、当前角色的个人基线时拒绝执行合作入房和客机世界覆盖；新建角色须先正常保存并重新读档。换角色、回标题、失败加载和新建角色作废旧凭据，同角色正常跨图保留基线谱系。 |
| 退出恢复和两代存档 | 退出凭据绑定当前进程持有的共享内存封印与序号；回标题先在内存作废，文件改名失败也不能重用旧凭据。核对主备两代实际目标，不能用空差异掩码认定完成。 |
| 存档导入与转换 | 校验实际载入目录、完整角色、profile 及存在的备档。替换前持久记录目标、临时目录、原件备份和哈希；中断后仅在证据完整时恢复，状态含糊则保留备份并阻止继续覆盖。普通版第一次初始化允许真正的空目录。奖杯仅按原生日志合并。 |
| 联机补丁 | 用可信重载代次识别地址复用；Lua 行为分派独立于日志采样。互伤过期关闭，恢复阵营前重新验证当前对象、角色身份和会话。每次钩子调用独立决定取消，避免并发共享跳过标志。 |
| 首次猎具迁移 | 先备份和预检，补齐并确认新猎具后才退休旧物品及设置领取标记，失败允许安全重试。保留空枪修复、房主纷争之铃声音及不自动重复补招募铃的行为。 |
| 启动器与更新 | 更新前持久保存替换计划和原文件备份；可捕获异常按完整计划回滚，进程被杀后的遗留事务阻止启动并指向恢复材料。内置服务端由客户端整体更新。清理下载临时文件，保留恢复备份；补齐回调异常、首帧检查和界面超时保护。 |
| 账号与服务端 | 账号助手以 stdin 接收密码和密钥；Windows 与 Linux 使用同一助手。重置密码轮换令牌，封禁使旧令牌失效。STUN 要求登录且来源 IPv4 一致。删除与召唤操作严格检查身份字段和所有权；在线数据读坏时保留原件并拒绝写入。 |
| 私服 Relay v2 | 原生账号令牌、随机挑战、会话 MAC 和序号验证；原生 Matching 决定房间与房主权限。四类召唤接口绑定 Bearer，入房前位置只发选中账号并支持超时与撤销。私服不回退旧广播或未认证 P2P；客户端、服务端须同步升级。 |
| NPC 赠礼保护 | 通用 9040 事件覆盖全部 30 个赠礼请求槽；回归核对本人实际请求后才调用一次正常奖励，并覆盖角色地址复用、主客与梦境条件切换。旧档中已经提前设置的标记需要独立取证，不自动猜测补发。 |
| 打包与说明 | 每次重新解开并校验固定服务端源码；源码按清单收录，生成文件明确列出。拒绝私人数据及临时变体，归档后重新检查成员、CRC 和逐文件哈希；补齐使用文档入口、部署说明和第三方通知。 |

## 已完成的本地验证

- 实际生成的 BBSC DLL、存档桥、启动入口、C# WPF 启动器、Windows 服务端及账号助手编译通过。
- 原生回归覆盖同地址跨图、普通效果移除、互伤过期与对象复用、迁移失败重试、成功/失败读档、角色切换、首次凭据发布失败、旧退出凭据作废失败，以及 80,000 次并发钩子调用。
- Python 回归覆盖主备目标核对、真实目录改名中断、完整来源校验、更新中断/回滚、凭据不进入命令行、隐私文件拒绝和源码清单。全部使用隔离的合成存档、账号与服务数据。
- 当前用户下的 DPAPI、WPF 页面与操作保护、更新界面、服务端界面及真实原生 HWND 布局检查通过。
- 服务端 CTest 使用实际编译的 Broker、安全边界和 stdin 助手，未连接真实服务。
- 客户端完整 Python 回归 315 项通过。服务端离线 Python 回归 19 项通过；Windows 原生 CTest 3/3、Linux 原生 CTest 4/4 通过。慢接收者用新连接能否认证同一账号核对服务端实际释放，避免 TCP 零窗口延迟通知造成误判。
- Windows 实际原生服务与生产 C++ 客户端协议代码完成账号、原生房间、跨房间隔离、房主迁移、签名、重放、令牌吊销、HTTP 所有权和定向传送提示撤销检查。测试使用新建的合成账号与独立状态目录。
- 实际普通版两个角色的主备两代未发现赠礼标记提前完成或物品索引重复/错位；与前一个测试包对应角色的全部 30 个赠礼位一致，原件前后摘要不变。桌面提供的另一组历史损坏存档单独处理。

具体测试数量及候选包哈希见随测试包提供的验证报告；跳过项独立列出，不算通过。

## 实机结果与剩余边界

用户已确认前一个加固测试包的登录、招募、入房、传送、离房、普通版导出和灯点正常；此前空弹动作、纷争之铃音效及回梦境不重复补招募提示的实测仍按对应版本保留。

认证版 Relay 是后续新增协议，尚需真实双机验证配套升级后的招募、提灯同行、互伤和离房。协议与容器结果不能证明全部游戏内时序、死亡/强退、角色切换或 NPC 实际对话领奖均正常。NPC 夹具核对发奖调用门槛，没有执行全部支线 ESD 或证明背包实际入账。新角色仍须正常保存并重新读档取得完整个人基线。

Linux 完整镜像及实际服务运行结果、候选包哈希与逐项证据随本轮验证报告提供；不表示现有私人服务器已升级。

## 已知协议边界

私服 Relay 与召唤接口已验证原生账号身份和房间权限，详见[协议与兼容说明](../server/docs/relay-auth.md)。底层 NP/HTTP 仍是原有明文传输；MAC 提供消息完整性与身份检查，没有提供内容加密。同一 NAT 内的 STUN 来源仍无独立密码学证明，旧公共内容接口也不在私服召唤认证范围内。部署继续使用受信玩家的明确 LAN/VPN 地址。

MSYS2、Qt 运行时有版本和许可清单，但系统软件仓库没有固定为完整历史快照；不能宣称所有二进制可逐字节复现。本次没有重新编译 BBport 核心，测试包复用已校验的公开 preview.21 中相同锁定版本 1.9.7 核心；BBSC、存档桥、启动器及服务端均为此次源码产物。
