# 本地开服与统一仓库

![启动器中的本地开服入口](local-server.png)

## 在启动器内开服

完整客户端包内置 `server/Server.exe`。打开 The Hunt 的「本地与云端开服」，点击「打开本地开服管理」，在管理窗口选择开服电脑实际的局域网或 VPN IPv4、启动无缝服务，并为每位玩家创建不同账号。

管理窗口独立运行；退出游戏或关闭启动器不会自动停服，结束开服请在管理窗口停止服务或关闭该窗口。打开窗口本身不会自动开服。

同机连接可点击「填入本机服务地址」，按钮读取本地管理器已保存的监听地址，再填写本服务创建的账号并保存。该按钮只填入四项连接地址，不改账号、密码、云端管理配置或存档，也不会自动保存。127.0.0.1 只供这台电脑使用；同伴填写开服窗口显示的局域网或 VPN 地址。

同伴连接需要放行 TCP 31413、31415、20443、20444 与 UDP 31414；工具不会自动修改防火墙或路由器。

## 独立服务端仍可使用

仓库内 `server/` 是完整的无缝服务端源码，普通联机模式已取消。其 shadNet、STUN、WebAPI、BBSC 游戏服务与 Relay、两秒轮询、账号数据格式保持原样。

同一发布页提供独立 Windows 服务端包、Linux 配方和固定上游源码；远程开服无需下载客户端引擎。原 TheHuntServer 仓库只读保存历史，新版本统一从 TheHuntLauncher 发布。

旧客户端仍沿用当前仓库检查更新。旧独立服务端的更新器指向历史仓库，首次迁移需手动下载新服务端包；此后使用新仓库更新。

## 数据位置与升级

内置服务端的数据在客户端目录的 `server/server.json`、`server/bbsc/` 和 `server/backups/bbsc/`；它们是联机账号与游戏在线服务数据，不是玩家角色存档。独立服务端仍在自身根目录使用相同相对路径。

升级前关闭本地开服管理窗口及其服务。自动更新替换程序并保留已有监听地址、账号库、注册配置、世界／记分板配置、在线数据与备份。不要整份复制另一台电脑已经配置过的客户端。

从旧独立服务端迁移到内置服务端时，停止旧服务并备份，将旧 `server.json`、`bbsc/shadnet.cfg`、`bbsc/db`、`bbsc/online-data.json` 及自改的 `bbsc/worlds.cfg`、`bbsc/scoreboards.cfg` 放到新包 `server/` 下的对应位置。只迁移实际存在的数据文件，不复制旧 exe 或 runtime。也可继续独立开服，由客户端填写该服地址。

旧 `normal/` 数据不读取、不转换或自动删除。无缝与普通账号不会合并。
