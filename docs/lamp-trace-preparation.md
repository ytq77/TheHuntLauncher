# 私人灯点诊断准备（当前预览版的独立副本）

本工具用于定位灯标记首次变化的阶段，不补开灯、不重放历史归档，也不构成历史根因已修复的结论。源代码在 `scripts/lamp_trace/`；`patches/bbsc_lamp_trace.inc` 仅由显式诊断构建加入，普通发行构建不包含观察代码。

## 观察内容

- 原生观察：37 个已解析灯标记所在组、会话、地图、own_world、加载状态、BBSC 推断的活动存档槽及已有世界记录槽。
- 分阶段前后对照：入房前、地图/梦境应用、梦境恢复、旧记录读取、世界恢复；作用域退出时记录，包括提前 return 的情况。
- 原生保存入口只使用带采样时间的缓存上下文，不把缓存当作一次新写入观察。
- 磁盘观察：只读选定槽的主文件和游戏备份，保留变化快照及开始/结束版本；未读到的组记为未知，不当作关闭。
- 原生记录上限 4096 行，磁盘二进制快照上限 256 份；摘要报告达到上限、读取错误和未配对操作，不能将缺记录解释为没发生。

游戏与既有 BBSC 本身仍会正常写诊断副本的存档；新增观察代码没有额外的游戏旗标写入。Guest01 的房主世界临时视图可能正常少于自己的灯数，摘要单独标注，不能把它直接当成永久损坏。

## 准备边界

私人包从已经核验的 preview.17 完整 ZIP 创建全新 `TheHunt-Lamp-*` 目录，核对发行摘要、程序清单、诊断 DLL 和基线种子。使用保留的 15 灯房主分支与指定客机历史副本；原件只读，种子和原始数据不提交仓库。它们不是当前录制进度的自动修复来源。

私人副本沿用 preview.17 原来的 `BBSC-Launcher.exe` 和完整 WPF 调用链，标题及版本栏标明 LAMP TRACE；自动更新入口、存档操作、玩法与开服导航隐藏。当前新名称 exe 的开发准备是另一项工作，不替换本诊断的已发布前台。副本内不携带账号凭据、配置好的连接地址或自己的服务端，需要停录后手动填写对应路径和账号。

每份副本只允许一次采样运行。观察与收集互斥；崩溃退出会释放操作锁，保留现有证据。出现读取失败、恢复失败或诊断错误时保留原错误和证据，不覆盖正常安装。

## 停录后的定向验证

1. 先确认两个私人 WPF 窗口的标签、实际路径、待用角色槽及记录收集功能。本轮离线准备没有打开窗口，不能代替此验证。
2. 在私人副本选择 case.json 对应角色。活动槽字段是 BBSC 既有的推断值，不是角色 UUID；需与用户选择、主备文件和场景记录交叉核对。
3. 02 为房主，01 为客机，按历史有关路径做入房、梦境往返、结束会话。主机自己世界中的灯减少时保留现场，停止追加操作；不把客机临时房主视图认定为丢灯。
4. 完全结束诊断后收集证据。对照各阶段前后值和两代存档；发现缺采样、槽不符或异常时先补相应证据。

已有商店、徽章、普通掉落、Boss 与标题退出验收按未改范围复用。即使本轮 15 灯保持不变，也只证明当前输入与执行路径，不足以解释历史不同分支的全部差异。
