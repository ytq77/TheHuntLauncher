# 无缝版 → 普通版：离线转换

新建导入、转换任务也会备份并合并双方真实奖杯记录，保留最早解锁时间；导出包携带记录，替换原版时自动合并。缺少来源记录会提示，不根据角色进度补发。详见[奖杯记录说明](trophies.md)。角色进度仍按下述规则处理，不因奖杯合并而合并剧情进度。

在 The Hunt「存档」页确认两份存档属于同一角色，直接选择：

- **导出普通版存档**：备份、离线转换副本、检查结构并导出 ZIP，两边真实存档不变。
- **转换并替换原版**：完成同样的检查和导出后，完整备份旧原版，再替换原版的整份 savedata。

转换全程不启动游戏，也不用提前手动卸下联机道具。工具自动清理快捷道具栏、当前选中道具和随身物品栏中的无缝道具引用；恢复的原版联机道具只放背包，其他物品和装备保持原样。

转换始终检查原版基准、无缝角色主存档和游戏备份的事件区布局，并要求输出的完整事件区与无缝输入逐字节一致；不因没有辅助记录而跳过。字段报告记录事件区摘要。**这只能证明转换没有改写剧情标记，不能证明输入存档的 NPC、任务或世界状态本来就正常。**输入已有的异常也会原样带到普通版，不会自动用旧原版的剧情进度修正。

## 从普通版导入无缝版

手动导入会将旧无缝存档和已完成的世界恢复记录、客机拾取记录一起保存在 `save-backups/import-时间-编号/` 中；联机记录放在其中的 `auxiliary/`，并从模组活动目录移出，避免新存档继续套用旧记录。失败时同时恢复存档和辅助记录。若回滚未完整完成，保留导入锁以阻止启动，错误信息会给出备份位置。

未完成的自己世界恢复记录、共享进度和未知记录会阻止导入，请先用原来的无缝分支完成恢复，不要直接删除记录。首次初始化同样核对复制完整性与源文件稳定性；若独立数据目录尚未初始化却已有旧联机记录，会停止并要求先保留、核对旧分支。

导入是整份进度替换，不会合并。将较旧普通版导入无缝版，仍可能主动回退整个分支；请先核对来源和备份，文件时间不能保证某条 NPC 任务线更新。

## 支持范围

当前针对固定 CUSA03173 1.09 的模拟器原始存档布局。只支持一名角色持有完整的五件无缝道具，携带数量各一件。逐件读取同槽位原版备份中四种原版联机道具的持有记录：持有的恢复一件，没有的保持没有，支持一至四件的任意组合。恢复范围只依据这份原版备份，不推测旧备份之后新获得过哪些原版道具。还会核对角色名称与外观，两份存档属于同一角色仍需用户确认；同槽位或同名不代表能够自动合并角色。

原版备份没有任何可确认的联机道具、目标数量异常或存放仓库、多个角色持有无缝道具、角色备份文件不符合条件、未知字段布局，均停止转换并保留副本。没有任何持有记录时不会随意补发四件；应先核对原版基准是否过旧或尚未领铃。

辅助记录随任务单独备份，按状态检查，不再仅因目录里有文件而停止：

- `own-world/own-save-N.bin.restored`：已执行恢复的历史记录，只备份，不重放旧世界状态。
- `guest-items/taken-save-N.bin`：仅支持本次目标角色的 `save` 标识记录。逐组核对物品拾取标记已经同时存在于该角色 `userdata` 和 `backup` 的事件标记区；缺一个也停止，不自动补写标记。
- `own-world/own-save-N.bin`：仍有待恢复的自己世界记录，停止转换。请用正常 The Hunt 加载该角色，不加入别人，在自己的世界等待恢复，然后从游戏菜单正常退出。重新检查文件后再转换，不要手动删除记录。
- 共享进度记录、临时文件、未知格式、其他角色的拾取记录仍停止。辅助记录校验针对固定游戏布局；不会尝试合并世界进度。

若刚执行过自己世界恢复，主存档可能已经正确，但游戏自带 `backup` 仍保留恢复前一代。此时界面会说明具体文件和缺失标记数量；再加载自己的角色并正常保存退出一次，使游戏自行更新备份。不用联机，也不要手动复制主存档盖住备份。后续已保存一致的存档不需要重复这一步。

ZIP 包含无缝分支的整份存档目录，只有目标角色的 userdata 和 backup 文件完成转换。其他角色保持无缝分支原样，不应称为多角色批量转换。原版旧进度只用于核对所有权；不覆盖无缝分支较新进度，也不合并两个分支的进度。

## 备份、替换和失败恢复

开始前正常退出普通版和无缝版。每次点击都创建新任务，先复制并逐文件校验两边存档；操作期间源文件有变化则停止。

每个任务位于安装目录 conversion-jobs/<任务编号>/，保留：

- backup：两份完整输入；
- backup/auxiliary：存在的三类辅助记录原样备份；
- auxiliary-check.json：辅助记录摘要、拾取标记持久化校验，以及不写世界标记的处理策略；
- verify/user/savedata：离线转换后的副本（目录沿用旧版命名，本流程不会打开游戏）；
- offline-fields.json：字段改动前后字节及哈希；
- job.json：来源、状态和验证方式；
- converted-save.zip：经 CRC 和逐文件 SHA256 校验的导出包。

选择替换时，工具先在原版所在卷准备副本，再把旧原版完整目录移至 savedata 同级的 save-conversion-backups/<任务编号及随机后缀>/savedata。界面显示备份路径。切换或校验失败会尝试恢复旧目录，失败现场保留，不自动删除。

「打开本次转换目录」进入整次任务目录，其中 ZIP 保留点击转换时的无缝进度，并已处理成普通版道具状态。「打开原版备份」在替换完成后进入被替换的旧原版备份；只导出时进入本次任务的 backup/ordinary/savedata。按钮提示显示完整路径，目录不存在时禁用。

替换会覆盖整份原版 savedata，包含其他角色；原版最新进度也会由无缝分支替代。无缝版真实存档和导出包始终保留。若仅想保留转换结果，请选择导出。

这些任务、备份、账号和暂存目录不会进入公开安装包或源码包。

辅助记录不会放进普通版 ZIP 或复制到普通版。它们留在无缝版原位置，转换也不会删除 `.restored` 或拾取记录。备份或检查期间记录有变化则停止，避免拿不同次游玩的文件一起转换。

`offline-fields.json` 的 `restored_original_goods` 明确记录本次恢复了哪些原版道具。未持有的不占输出条目；多余的无缝条目会全部清空，并按实际恢复数量更新背包计数。旧的分步诊断仍使用四件原版道具齐全的检查条件，部分持有场景请使用主要离线入口。

## 验证记录与边界

一个 RTX 5070 本机角色已完成离线生成、普通版核心无模组重载、正常保存，以及保存后的字段复核：五件无缝道具消失，四件原版道具各一件，只在背包；快捷栏、当前选中道具和随身物品引用清空，其他物品、装备、进度和画面正常。两边真实存档未变。

本样本每个角色文件修改 49 个字节，无额外校验重算。读写器按文件头声明的有效角色区处理；文件尾部可能保留旧数据副本，不能全文件搜索替换。未知布局停止，而不是自动套用这些偏移。

自动检查覆盖结构、计数、装备索引、原版所有权、同角色、重复引用清理、尾部旧副本、源文件变化、导出完整性以及替换备份和回滚。其他角色和电脑尚未实机验证，自动检查不能替代这些验证。

## 旧任务／诊断

折叠的「分步诊断」保留已验证的四次加载流程，用于旧任务和排错：原版检查、无缝装备检查、游戏内转换、普通版重载后人工确认导出。它与主要的离线入口分开；离线入口不要求勾选旧诊断流程的“已卸下”或“重载验证”复选框。
